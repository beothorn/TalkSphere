# Services requester callbacks

The installed definition is immutable and independently standard-validated.
Terms checks current exact Storage economics. Scoped pricing receives the original
Services-authorized Peer and current Offering, independently known metadata and
provider factors. Application requester comes from the operation key; provider
comes from the authenticated opposite role, independent of TCP direction or issuer.

Store quotes use positive original size/duration projection with empty factors.
Retrieve uses the original owned lease, subtraction-safe range and current maximum;
remove uses current exact removePrice. Renew requires the exact sole sizeBytes
factor to match the original provider-scoped snapshot, current expected expiry,
duration and total-retention bounds. Calculations reuse exact integer Storage
pricing. Quote checks reserve no money, execute no work and mutate no catalog.
Context-free pricing and remote factor validation are explicitly Unsupported.

Metadata projection validates bounded original input and current offered store
limits without copying data/hash into quote metadata. Complete-input validation
checks standard semantics and matches the original accepted projection. Unknown
compatible extensions remain bounded inert data; known fields for another
operation, malformed lengths, duplicates and changed dimensions fail.

Complete contextual result validation receives original public Invocation,
original complete input and output. It checks the exact installed contract and
operation semantics, then delegates to independent store/retrieve/renew/remove
validators. Store observes the requester receipt clock under configured tolerance;
other operations read original scoped lease expectations. Optional private range
bytes are compared when available; complete objects are rehashed. Remote
count/range/output checks happen before any private range dependency can read
or allocate its requested bytes. No result
validation writes the catalog, applies a provider mutation or settles credits.

The legacy postcommit local verify port has no typed Invocation and never decodes
Services-private accepted/journal bytes. It compares explicitly supplied original
retrieval bytes with complete associated retrieval output. Missing/ill-sized
expectations or another operation is inconclusive. This conclusion compares bytes;
it is not a replacement for mandatory contextual result validation or proof of
physical provider durability. It never refunds a charge or changes trust.

Missing/unowned original expectations fail Denied; stale guards Conflict;
unknown/unscoped contracts Unsupported; malformed fields, prices or results
Invalid; budget/arithmetic exhaustion Limit; dependency failures preserve meaning.
