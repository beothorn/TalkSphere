# Cached Messaging binding

Lookup supplies the real Registry, separate Services Recover/Observe contexts and
original Coordinator. provider requires incoming Invoke permission and the trusted
original association. It probes only Messaging invoke recover/remove proposals,
before current Board selection, new pricing, balance or pending-state checks.
Registry.recover retrieves retained codecs even after drain without installing
code. Defined metadata is bound through that schema; unresolved required ownership
keys are Unsupported, with no placeholder values. Ignored compatible extensions
cannot change the operation. Services then checks original caller, every defined
request/control field and original family-approved commitment. No match returns
no cached result; matching uncertain work stays Unknown.

request encodes only an explicitly minted Services Retry under outgoing Request
permission. It preserves original offering/publisher/issuer, defined request,
spending ceiling and optional payment. There is no new quote, acceptance or input
body. A local caller must request this operation explicitly; ordinary interrupted
work is never retried automatically.

Sender consumes opaque original-owner Cached proof, uses the original output
schema/final price and queues result, detached bodies, result.end and END after
queue drain. proof authorizes the narrow Exchange cached-local transition.
Exchange.cached_remote instead requires the explicit requester Retry. Both require
a matching propose phase and correct role; ordinary early result controls remain
illegal. The requester may half-close after receiving cached result metadata.

ResultReceiver.for_retry binds original terms to the approved new stream and keeps
all output provisional until exact bodies, result.end and normal completion. Its
owner applies the complete result only to the original payment key. A failed or
interrupted retry does not release the original obligation. No new payment,
execution, generic job-status or resume operation is introduced.
