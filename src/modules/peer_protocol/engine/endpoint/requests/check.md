# Explicit remote check request

`Challenge` supplies a sealed provided selection, its direct metadata cache, only
the public check.input value, the original spending/payment bound and a separate
local `CheckConsent`. Private expected evidence stays in the installed requester
and later local outcome query; it is never a request-plan field or provider outcome.

`CheckConsent.approve` receives an independently validated immutable check Candidate
and returns a ceiling or typed refusal. The explicit local `Ceiling` policy also
implements this contract; zero is valid only after the actual check owner proves
an included entitlement. Ordinary zero-price work cannot enter this path.

Acceptance rechecks current direct metadata, exact quote hash, installed family
rules and real owner capacity, then reserves before emitting accept/input.end.
No detached private expectations or fabricated resource identifiers are sent.
Requester END waits until all input controls drain into Transport. The send stamp
uses that original drain observation in a stable local clock epoch, even if the
worker callback runs later. It is a conservative local admission observation,
not a remote receipt or physical-write acknowledgement.

Evidence remains provisional until exact records, result.end and actual normal
Transport completion. The original complete-response observation supplies the
receive stamp, avoiding worker-delay changes to timing. The real Services owner
validates evidence/window, stages it and commits local participants. A Check reply
contains the original local operation key; query its outcome separately with local
private expectations under Observe authority. Missing expectations are inconclusive.

Paid/included accounting and allowance consumption stay in Services/Ledger.
Interrupted responses remain unknown without a refund or new financial attempt;
normal authoritative failures use the original abort gate. The unresolved paid
lost-response ambiguity remains [CR2SE issue10](https://github.com/beothorn/CR2SE/issues/10).
