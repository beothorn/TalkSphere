# Provider check quotes

Owner.issue requires incoming Invoke authority, separate Services Invoke context,
owner-authorized check Proposal, bounded Current checker and finite local expiry.
It accepts complete bounded challenge metadata, validates installed Rules,
existing entitlement/authorization, fixed check price and independent evidence
binding before any hold or evidence execution. Unresolved pre-quote ownership
keys are refused Unsupported; no placeholder IDs or bytes are invented. Canonical
outgoing fixed challenge IDs fit inline. This refusal is a local capability limit,
not a new prohibition on detached values in the protocol.

Paid price plus exact preagreed issuer fee must fit the original total ceiling.
Included checks require zero new charge and no transfer. Entropy supplies fresh
32-byte quote IDs. Exact JSON, SHA256, current offering/issuer, original payment,
challenge, mode, response budget and original association remain immutable under
finite expiry and quote count. Issued exposes bytes/hash/ID/price/association only;
creation is neither a reservation nor evidence.

Owner.accept requires the original opaque owner/generation, original stream and
exact quoteId/hash. Separate Services Invoke/Coordinate grants admit the original
Agreement, recheck current/frozen terms and reserve actual capacity once. Incoming
is still gated on input.end and requester END before evidence dispatch. Invalid
acceptance releases its original transient slot; uncertain durable admission is
not rollback. discard releases only the original unaccepted generation and never
changes accepted coordinator work. No remote job/status/retry operation is added.
