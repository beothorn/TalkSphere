# Remote check ownership

Config supplies local identity, separate Peer Protocol/Services authorities,
explicit Registry, finite Limits, read-only economic Gate and quote Entropy.
Owner validates local ownership and retains a bounded expiring quote domain.
It neither installs handlers from descriptions nor creates ordinary zero-price work.

Request/quote/consent/acceptance capabilities belong to one opaque owner and the
original authenticated association. Checks use the exact installed Rules and a
separate provider-evidence schema, never the requester-computed check.output.
Paid work uses positive checkPrice; included zero-price work must name an existing
finite owner-scoped entitlement. Services independently freezes and rechecks the
quoted mode, price and response budget at durable admission.

Provider, requester, state, input, evidence and clock companions describe the
public operations. Expectations enter only the existing local Services outcome
port after evidence; no wire-check API accepts an expected value or a provider
pass/fail claim. Ordinary invocation ports remain separate.
