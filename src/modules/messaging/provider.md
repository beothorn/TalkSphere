# Provider

The provider engine for the store operation. It never charges or records anything before the final commit.

- `StoreHeader`: the signed metadata, sender key, sender signature and requested retention, i.e. everything except the payload bytes. `StoreInput.header()` extracts it.
- `Provider(terms, participant, clock, staging)`.
- `assess_store(caller, header)`: before the body is received, checks that the sender is the authenticated caller and derives from the supplied key, the payload size is between 1 and the offering maximum (at least 105 for the encrypted encoding), retention is within the offering bounds, the expiry does not overflow, and calculates the exact price. Reserves staging space. Returns an assessment holding the price and reservation, or `Invalid`/`Limit` with nothing reserved.
- `prepare_store(key, assessment, message)`: requires the message to equal the assessed header, verifies size, hash and signature (the signature covers the payload, so this can only happen now), then prepares the effect durably with a new placement ID.
- `commit_store(prepared)`: commits and returns placement ID, message ID, acceptance time, expiry and price. The acceptance time is assigned at the durable commit.
- `store(key, caller, input)`: the three steps in one call. Dropping the assessment releases the reservation.
- Every failure before commit leaves no placement, no journal entry and no reservation.
- `discover(caller, input)`: lists the caller's pending, unexpired placements ordered by `(acceptedAt, placementId)` strictly after the optional cursor, at most `limit` (1 to the offering maximum, else `Invalid`). `more` is true when another entry follows. Read-only; the price is the fixed discover price, an empty page included. Entries show the sender only as a hint.
- `recover(key, caller, input)`: verifies the recovery request, calculates the exact recovery price from the payload size and has the participant atomically record the provider-signed receipt and move the placement to recovered. Returns the original signed message and receipt plus the charged price (the output itself has no price field). An unknown, expired, non-pending or foreign placement, or a mismatched message or hash, is `NotAvailable`; a bad signature is `Invalid`. Nothing changes or is charged on failure.
- Recovery retry: when the caller repeats a recovery with the recovery ID already recorded for the placement (a new operation), the provider verifies the request again and returns the recorded message and receipt with the original recovery price, applying and charging nothing new. The record keeps that price, so the answer survives restarts, price changes and renewals. A different recovery ID for a recovered placement is `NotAvailable`.
- `status(caller, input)`: tells the placement's sender whether it is pending or recovered, with the exact recorded receipt when recovered and never the payload. Read-only; the price is the fixed status price. An unknown, removed, expired or foreign placement is `NotAvailable`.
- `renew(key, caller, input)`: extends a pending or recovered placement for its sender. The input names the expiry the sender saw and the seconds to add (within the offering's minimum and maximum duration, else `Invalid`); the new expiry may not pass acceptance plus the total retention limit (`Limit`). A stale expectation is `Conflict`, so of concurrent renewals naming the same expiry exactly one wins. An unknown, removed, expired or foreign placement is `NotAvailable`. The state does not change; the exact renewal price is charged once and added to the placement's payments.
- `with_release_policy(policy)`: installs the early-release policy; without one no credits are offered.
- `quote_removal(caller, input)`: returns the exact `releaseCredits` and the removal price before anything changes. The policy's answer is bounded below by the sender's minimum and above by the placement's cumulative store and renewal payments; other operations' prices never enter those payments. `NotAvailable` unless the placement is pending, unexpired and the caller's; `Conflict` for a stale expiry; `Invalid` when the minimum exceeds the payments; `Limit` when the policy offers less than the minimum.
- `remove(key, caller, input)`: quotes the removal, then records it and issues the quoted credits exactly once under the operation key through the participant. Returns the placement, removal ID, `removed = true`, the credits issued and the removal price. Quote errors apply, plus `Insufficient`/`Limit` when the credits cannot be issued and `Unsupported` when no issuer is installed for a positive amount; failures before the record changes leave the placement pending.
- Removal retry: when the sender repeats a completed removal with the removal ID already recorded for the placement (a new operation, any time later, even after a restart), `remove` returns the recorded result from the durable record and neither prepares nor issues anything. A different removal ID or a different caller is `NotAvailable`.
- `check(caller, input)`: serves the single payload byte at `offset` of a pending, unexpired placement to its sender as paid evidence. Read-only. An unknown, inactive (recovered, removed, expired) or foreign placement is `NotAvailable`; an offset at or beyond the payload size is `Invalid`. The check price is charged by Services only for a complete valid response, never for a refusal.
