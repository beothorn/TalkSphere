# Explicit family cached retransmission

Purpose is Recovery or Removal. Id binds that purpose, the original32-byte
placement and recovery/removal ID. It is never a generic input hash or a global
identifier independent of resource/caller scope. Requester.cached_retry explicitly
identifies eligible family requests; its default returns no permission. Provider's
allow_cached_retry separately approves original cached ownership/retention, with
no current price, balance or pending-state lookup; its default refuses.

Proposal contains fully decoded service/version, offering, publisher, issuer,
original total maximum, original Payment and complete defined input. A trusted
adapter supplies authenticated Peer separately. Unknown compatible extensions
cannot alter the version-one operation or its replay identity.

Cached is created only by the original coordinator after every original request
field and caller binding matches retained committed work and the family explicitly
allows retransmission. Its invocation/completion getters retain identical original
terms/output/price. peer names the new authenticated response stream. No new
reservation, execution, credit release or charge occurs.

Retry is an opaque requester capability minted under separate Request and Observe
permissions for an original already dispatched Messaging operation. It retains
original financial key, input, Invocation, payment/ceiling and approved new Peer.
Read-only getters expose those bindings. It does not authorize generic work
retry. The original coordinator alone may remap validated retry results to the
original financial key; tokens cannot cross coordinator instances or restarts.
After restart a new explicit token must be minted from recovered original history.
